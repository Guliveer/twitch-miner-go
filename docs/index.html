It finds the streamers.

You configure a rule, not a list. The miner looks for channels that match it and keeps watching the ones that pay out — new streamer, same config.

Category watcher

Watches live channels in a game category you name. A stream that starts later is picked up without touching the config.

Badge watcher

Opt-in discovery of streams that reward watch-time chat badges, driven by the community catalogs the Python miners maintain.

Team watcher

Follows Twitch team membership, so every live channel on the team joins the watch set.

Followers mode

Watches everyone you already follow, optionally ordered by viewer count. Combine it with a blacklist when an account follows hundreds of channels.

Collected while you were away.

Every routine claim has its own toggle and schedule, per account.

  • Drops

    Campaign progress is synced and each reward is claimed as it unlocks.

  • Channel points

    Minute-watched events and bonus chests, with a narrowed watch set for streaks.

  • Bonuses

    Available bonus claims are collected instead of expiring unattended.

  • Predictions

    SMART, HIGH_ODDS or MOST_VOTED strategies with a point cap and a bet delay.

  • Raids

    Joins the raid when a watched channel ends, so the points follow the host.

  • Moments

    Community moments are claimed while they are available.

  • Goals

    Contributes to active community goals when the account has points to spare.

Run the script

Requires Go 1.25 or newer. The script builds and starts the miner in one step.

Shell 
git clone https://github.com/Guliveer/twitch-miner-go.git
cd twitch-miner-go
./_run.sh

On Windows use _run.bat.

Container

Docker

A ~12 MB image. Mount the config directory and a data volume so cookies survive a restart.

Shell 
docker run -d --name twitch-miner \
  -p 8080:8080 \
  -v miner_data:/data \
  -v "$PWD/configs:/configs:ro" \
  -e DATA_DIR=/data \
  --env-file .env \
  ghcr.io/guliveer/twitch-miner-go:latest

Docker Compose, systemd, OpenRC, a Windows service and Fly.io are documented in the README.

Five steps to a running miner.

Download, one YAML file, one login. Everything else has a default. The wiki has the long version with every flag and option.

  1. Download the archive

    Take the Windows, macOS or Linux build from Releases and unpack it. The binary is the whole program — no runtime to install.

  2. Create one config

    Copy configs/example.yaml.example to configs/<your_twitch_username>.yaml. The filename is the account name; the example explains every key.

  3. Start the miner

    Run the binary, or from a clone double-click _run.bat on Windows and run ./_run.sh on macOS and Linux. On a desktop, the tray icon opens the dashboard and the config editor.

  4. Sign in once

    Approve the device code at twitch.tv/activate. The token is saved as a cookie, so every later start is unattended; headless hosts pass TWITCH_AUTH_TOKEN_<USERNAME> instead.

  5. Open the dashboard

    Analytics on localhost:8080, the config editor on localhost:8070 in file mode. Both ship inside the same binary.

Accounts

Many accounts, one process

Each account has its own YAML config (or a PostgreSQL row), its own cookies and its own notification channel. YAML changes hot-reload without a restart.

DB mode replaces files with a REST API and survives a redeploy without a config volume.

Built in

Dashboard included

Analytics on :8080, a config editor on :8070 in file mode, and event logs. Nothing else to host, nothing to sign up for.

Questions people ask first.

The long version lives in the project wiki.

Do I need Go installed?

No. The release binary is self-contained. Go is only needed to build from source or to run the standalone config editor from its script.

What happens on the first run?

The miner walks through authentication until one method succeeds. In an interactive terminal that means a device code: it prints a code, you approve it at twitch.tv/activate, and the token is saved for the next start. Headless hosts can supply TWITCH_AUTH_TOKEN_<USERNAME> instead.

How do I add a second account?

Drop a YAML file into configs/ named after the Twitch username — the filename is the username, there is no field inside. The file watcher starts the new account without a restart.

Do config edits need a restart?

No. YAML changes hot-reload by default. An invalid config is skipped and a disabled account is stopped with a line in the log; set enabled: false to pause an account without deleting it.

Does it actually watch the stream?

No video or audio is played. The miner sends minute-watched events every 20 seconds for the streamers it picked, which is what Twitch counts for points, streaks and drops.

Does it collect any data?

Anonymous telemetry is on by default: instance ID, version, OS, architecture and the number of running accounts. No usernames, channel names, IPs or tokens. Turn it off with TELEMETRY_AGREE=false.

Why does Docker lose the account after a restart?

Cookies, state and the instance ID live in /data, configs in /configs. Mount both as persistent volumes — without -v miner_data:/data they vanish with the container.

Can it update itself?

With -auto-update it downloads the release for your OS and architecture, replaces the binary and exits so the service manager starts the new version. On Windows the running executable is moved aside first, because Windows will not overwrite it in place.

Is it open source?

Yes — GNU GPL v3.0. The source, the issue tracker and the release history are all on GitHub.
